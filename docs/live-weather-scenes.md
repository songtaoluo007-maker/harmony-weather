# 在线天气与城市动态场景

## 默认直接可用

默认 `weather_config.json` 的 provider 是 `openmeteo`。无需登录或密钥；应用在
原生 NetworkKit 中通过 HTTPS 请求城市经纬度对应的天气、24 小时预报、15 日
预报和日出日落。空气质量是独立的可选请求，失败或字段不完整时显示暂不可用。
网络访问已在本机 HarmonyOS 模拟器验证，不是浏览器展示页。

数据源是气象模型的当前值/预报，不保证与和风或气象站逐点实测一致；15 日后段
不确定性更高。空气质量采用 US AQI，不是中国 AQI；生活提示由本地规则派生。
当前适配器未接入官方气象预警，不制造“暂无预警”的安全判断或示例预警。

15 日详情中的“全天概况”保留每日天气码；“夜间”从当日日落至次日日出的逐小时
天气码汇总，并显示太阳时段、覆盖数量及数据不完整状态。后台请求 16 日来补全第
15 夜，界面仍为 15 日。没有可靠夜间数据就显示暂无，不用白天天气代替。
生活区保留原有六个入口并额外显示温差；旅游与感冒当前没有可靠指数，显示暂无数据。

免费端点适合个人、非商业原型，官方限制为每日 10,000 次计费调用且无可用性保证；
多变量、超过两周的查询可能按多次计算，不能简单等同于 HTTP 请求数。
参见 [Open-Meteo 使用范围](https://open-meteo.com/en/pricing)。
请求仅发送选定城市的经纬度与天气参数，不上传账户、密钥或设备标识。

## 如何跟随真实时间与天气

1. 使用接口返回的时区偏移计算城市当地日期与时间，不直接用设备的小时判断。
2. 从对应预报日读取日出、日落（分钟精度），区分晴昼/晴夜；雨、雪、雾、雷暴
   也有独立的昼夜属性，白天下雨不再总是渲染成黑夜。
3. 每分钟检查时间变化；天气按设置的 15/30/60 分钟间隔在前台刷新，也可下拉刷新。
   返回首页时会重新检查时刻与数据是否过期；不是每帧调用 API。
4. 按城市 ID 选择白天或带建筑灯光的夜间照片，再叠加缓慢云层、远景雨线与前景
   玻璃水滴；雪天叠加分层飘落的雪粒。城市建筑照片本身不是视频/摄像头，移动的是独立的天气层。
5. 页面隐藏、背景滚出屏幕或关闭动态效果后停止动画。当前是应用内开关，尚未
   跟随操作系统减少动态效果选项。

设置中的六种场景只用于检查画面，并始终显示“背景预览 · 天气数据未更改”。
退出预览后恢复自动场景；预览不能把当天晴天的真实数据改成“正在下雨”。

## 缓存与数据身份

持久缓存以 `provider_city_ID` 区分 Open-Meteo、和风与演示数据。网络失败只恢复
当前城市、当前数据源的缓存，保留数据时刻并显示离线标识；没有对应缓存就进入
失败重试。缓存恢复仍按当前城市时间决定昼夜，但旧天气本身可能已过期。
旧版未分源缓存不会直接当成新服务的真实数据使用。

## 和风天气接口预留

复制根目录 `weather_config.local.example.json` 到
`entry/src/main/resources/rawfile/weather_config.local.json`，配置 API Key 与自己
控制台分配的 API Host。旧共享域名正在退出使用，见
[和风 API Host 文档](https://dev.qweather.com/en/docs/configuration/api-host/)。
该本地覆盖文件不入 Git；构建后会进入 HAP，不能作为生产级密钥保护。生产应走
服务端代理。原来的和风适配器保留，但没有有效凭据，本轮未重新验证其账户权限、
15 日预报套餐或旧空气质量接口。建议在恢复凭据后单独联调，不声称此路径已验收。

## 城市资源扩展

目前仍为原项目的 15 城市目录，不是全球城市搜索。每个城市已有白天和夜间/暮色
资源，切换无需现场生成图片。新增城市要补充有效经纬度及经过许可审查的图片清单。
`scripts/fetch-night-backgrounds.ps1` 可批量查询候选；审查后写入
`design/city-night-selected.json`，运行 `-Download` 下载并生成 ArkTS 映射，或
`-GenerateMapping` 仅更新映射。刷新先验证临时图片，再替换资源，避免失败下载破坏旧图。
没有匹配夜景时显示通用夜空，不把别的城市当成该城市。

来源、作者和许可证在页面底部及 [夜景清单](../CITY_NIGHT_SOURCES.md) 提供。
截图和运行验证范围见 [design-qa.md](../design-qa.md)。
