# 城市天气 UI 改造

延续已确认的现代 OriginOS 方向，以 `design/originos-weather-target.png` 中的城市天空、纤细温度和连续预报为视觉依据。此次为原生 ArkTS 页面迭代，不创建网页替代品。

- 首页：44vp 触控区域、24vp 内容边距、轻量城市标题、112vp 温度；给城市景色独立留白。去掉预报外层重复卡片，使用细分隔线。逐小时可选，展示所选时段描述；逐日展示共享刻度的高低温曲线。
- 生活：三张独立生成的材质插画对应穿衣、防晒、运动，其余项目沿用现有授权图标。详情使用可阅读对话框。
- 二级页面：统一深墨蓝背景、18–24vp 圆角、清晰的返回与选择状态。城市列表用城市照片建立辨识度，避免虚构其他城市温度。
- 动效：天空、远景雨、玻璃水渍独立运动。天气状态和动效设置变化时重新启动；页面隐藏时停止，重新进入恢复。背景层不接收触摸事件。
- 数据：沿用现有和风天气请求与本地配置。首页明确显示演示/离线/和风来源。演示缓存不伪装成实时缓存；不修改或猜测用户密钥。
- 验证：Hvigor 未签名 HAP 构建；模拟器首页、城市、设置、详情和动效检查；窄屏与字体缩放验证，逐项记录实际验证范围。

## 本轮交付

- 首页、预报、空气质量、生活气象、指标详情、城市管理和设置的原生界面改造。
- 3 张原创材质插画、MIT 天气图标与第三方授权记录。
- 云层、远景降雨、玻璃水滴的独立动画；页面隐藏和背景滚出时停止。
- 城市按 ID 保存/移除；设置写入失败后恢复旧值；真实 API 失败不会拿演示缓存冒充实况。
- 7 项数据/状态测试，未签名 HAP 构建和实际模拟器截图。验证边界见根目录 `design-qa.md`。

## 后续优化优先级

### P1：真实数据与生产安全

- 先恢复本机和风天气开发配置并验证该账户对应的服务地址、鉴权和预报权限；本轮没有找到本地密钥文件，不猜测用户原密钥，也不把演示数据标成实况。
- 将各接口的“无权限、暂无数据、请求失败”细分，缺失的空气质量/预报指标显示缺省状态而非数值 0；天气预警和生活指数需要真实服务字段逐项验收。
- 分开降水量（mm）和降水概率（%）的模型含义，避免旧接口映射混用。生产版通过服务端代理保护凭据；正式证书不提交 Git。

### P2：城市与系统体验

- 对接真正的全国/全球城市检索和分页，再做收藏拖动排序；目前搜索仍是已有 15 城的本地目录。
- 新增城市时使用可授权照片源与统一动态天气层，不需要逐城生成视频；对图片查询失败提供明确的通用天空回退。
- 日夜计算使用城市时区，定位使用真实行政区结果而非仅选择附近已支持城市。
- 补充 390/480vp、横屏、平板、读屏和更大字体验证；接入系统减少动态效果设置。
- 实机测量低端机帧率、切后台耗电和纹理内存，再决定动画更新节奏和图片分辨率档位。当前已限制离屏动画，但没有宣称完成性能基准测试。

### P3：视觉精修

- 为清晨、日落增加随时间平滑过渡的光色；必要时增加晴天微弱日光资源，但避免遮住温度。
- 生活气象继续增加具体物件图，而不是回到 Emoji；风格保持当前材质、光向和低饱和色。
- 对所有城市照片做焦点标注与按设备比例裁切，改善当前统一下部取景策略。
